# Chromium Tab Picker · редизайн

Локальный fuzzy finder открытых вкладок Chromium. Горячая клавиша показывает
панель в iframe поверх текущей страницы. Расширение не создаёт окон или вкладок.
Работает без сборки, внешних серверов и runtime-зависимостей.

## Установка и обновление

1. Откройте `chrome://extensions`, включите **Developer mode**.
2. Нажмите **Load unpacked** и выберите `/home/user/Work/chromium-tab-picker`.
3. В `chrome://extensions/shortcuts` проверьте **Open tab picker over the current page**.
   По умолчанию — **Alt+Q**, область действия — **In Chromium**. При конфликте с
   QuicKey или Hyprland назначьте свободное сочетание.

При обновлении уже установленного расширения нажмите **Reload** на его карточке.
Обновите страницы, где ранее вызывали пикер: content script живёт до перезагрузки
документа. Не удаляйте каталог установленного расширения.

## Интерфейс

- Одна панель шириной 760 px с адаптацией к viewport. Пустое поле ввода сразу
  получает фокус. Верх панели остаётся на месте при изменении числа результатов.
- Квадратная панель без скруглений, компактная область поиска высотой около 38 px.
  Заголовки 17 px, домены 12 px, время 11 px. До 10 строк по 60 px;
  в маленьком окне прокручивается только список.
- Слева favicon, заголовок и домен; справа компактное время активации.
  Полный URL участвует в поиске, но не отображается. Нет номеров и технических ID.
- Без запроса — MRU; при запросе — fuzzy relevance, затем MRU и стабильный
  порядок окна/позиции/tab ID. Заголовки имеют повышенный вес относительно URL:
  конкретный ChatGPT-чат приоритетнее совпадения с общим доменом.
- Совпавшие символы заголовка выделены жирным без изменения оттенка или яркости.
- Изменение запроса выбирает первый результат. Фоновое обновление вкладок
  сохраняет выделение по ID; при удалении выбирается ближайшая строка.
- Нейтральная тёмная палитра, без категорий, счётчиков, префиксов, футера и
  управляющих иконок. Подсветка выбранной строки — только сдержанный фон.

## Давность и яркость

Worker хранит фактическое время событий `tabs.onActivated` и фокуса окна
`windows.onFocusChanged`. Для сфокусированного окна отмечается его активная
вкладка. Записи закрытых вкладок удаляются; при замене tab ID известная отметка
переносится. Состояние находится в `chrome.storage.session` и переживает
перезапуски service worker, но не завершение сессии браузера.

Для вкладок без наблюдавшейся активации отображается **—**. Они располагаются
после известных MRU в детерминированном порядке. `Tab.lastAccessed` и история
посещений не подставляются вместо собственной истории активаций.

Перед поиском полный набор вкладок сортируется по MRU. Яркость линейно убывает
от 100% до 65% по месту в этой сортировке. Порог 65% выбран для читаемости
вторичного текста на фоне выделения `#222`. Цвет заголовка — grayscale 238 ×
яркость, домена и времени — 212 × яркость. Favicon затемняется CSS-фильтром `brightness` по той же шкале 100–65%.
Полоса прокрутки скрыта; колесо мыши, клавиатура и автоматическая прокрутка
выбранной строки работают. Общая opacity строки не используется; выделение не меняет цвета текста.

Фильтрация и fuzzy-сортировка сохраняют исходные цвета вкладок. Шкала
пересчитывается только при изменении полного набора/порядка MRU. Подписи времени
обновляются каждые 30 секунд без перестройки списка.

## Клавиатура

| Сочетание | Действие |
| --- | --- |
| Alt+Q (настраивается) | Открыть/закрыть overlay |
| ↑ / ↓ или Ctrl+P / Ctrl+N | Выбрать результат, по кругу |
| Enter | Активировать вкладку и соответствующее окно |
| Escape | Закрыть, вернуть прежний фокус, если возможно |
| Ctrl+A | Выделить запрос стандартным способом |
| Ctrl+Backspace | Очистить весь запрос |
| **Ctrl+Alt+W** | Закрыть выбранную вкладку, сохранив пикер |

Обработчик **Ctrl+W** также существует, но в обычном окне Chromium это
зарезервированная команда закрытия текущей браузерной вкладки. Она может
выполняться до доставки клавиатурного события iframe. Для надёжной работы
в Linux используйте **Ctrl+Alt+W**. Расширение не меняет браузерные или системные
сочетания. Закрытие вкладки с самим overlay неизбежно удаляет и его документ;
автоматическая инъекция в следующую вкладку потребовала бы дополнительных
разрешений. Для продолжения вызовите пикер снова.

Можно выбрать результат мышью и закрыть панель щелчком снаружи.
Пока пикер закрыт, он не перехватывает ввод сайта.

## Архитектура и разрешения

- `background.js`: API вкладок/окон, команда, MRU, проверка клиентов, активация
  и закрытие вкладок. `storage.session` сохраняет MRU и токены iframe.
- `content.js`: существующий механизм разовой инъекции, manual popover в top
  layer, закрытый Shadow DOM и iframe; восстановление фокуса и скрытие overlay без удаления iframe.
- `picker.html`, `picker.css`, `picker.js`: один UI для iframe и toolbar popup.
- `search.js`: исходный fuzzy engine с усиленным приоритетом заголовков.
- `recency.js`: полная шкала яркости, сортировка MRU, домены и относительное время.

Разрешения: `activeTab`, `scripting`, `tabs`, `storage`, `favicon`.
Нет постоянных content scripts, host permissions, чтения истории или закладок.
`web_accessible_resources` разрешает встраивать только HTML пикера с динамическим
URL. Иконки берутся из favicon API Chromium. Нет CDN или remote scripts.

Сообщения UI идут через runtime Port. Worker проверяет ID расширения,
схему/путь документа, имя порта, тип сообщения и целочисленный tab ID. Для iframe
требуется случайный токен его вкладки. Контент проверяет ID отправителя и токен,
не принимает команды через `window.postMessage`. Строки вкладок выводятся как
текст, без HTML-интерпретации.

## Ограничения

- На `chrome://`, Chrome Web Store, встроенном PDF viewer и других запрещённых
  страницах команда пытается открыть обычный toolbar popup. Если окно потеряло
  фокус или браузер отказал, нажмите кнопку расширения. Отдельных окон нет.
- `file://` требует **Allow access to file URLs**; инкогнито включается отдельно.
- Фокус внутри стороннего iframe сайта восстанавливается только до самого
  iframe. Сайт, намеренно меняющий фокус или удаляющий overlay, может мешать UI.
- Запрос фокуса другого существующего окна обрабатывается Chromium/Hyprland;
  правила workspace и системные сочетания расширение не меняет.
- Одинаковые заголовки и домены не получают технических меток согласно дизайну;
  строки остаются разными вкладками по внутреннему ID.
- Ctrl+W и закрытие вкладки, в которой размещён overlay, ограничены архитектурой
  браузера — подробнее в разделе управления.

## Проверки

Для разработки: Node.js 20.11+, установленный Chromium.

```sh
cd /home/user/Work/chromium-tab-picker
npm ci
npm test
npm run test:e2e
```

Интеграционный тест рассчитан на Linux/Hyprland с Lua API: нужны запущенный
Wayland-сеанс и `hyprctl`. Он открывает два настоящих окна отдельного
временного профиля и отправляет системные клавиши. Во время теста не вводите
текст в тестовые окна. Пользовательский профиль не используется.

`CHROMIUM_PATH=/path/to/chromium npm run test:e2e` выбирает бинарник.
`LIVE_SITES=1 npm run test:e2e` добавляет проверку публичных GitHub и ChatGPT.
Артефакты: `test-results/overlay.png`, `test-results/results.json`.

Модульные тесты проверяют fuzzy relevance, MRU, неизвестную давность,
восстановление состояния worker, очистку закрытых вкладок, форматирование времени,
порядок равных совпадений, приоритет заголовка и сохранение яркости при фильтрации.
Интеграционный сценарий проверяет 30+ вкладок и два окна, горячую клавишу,
фокус, размеры панели, отсутствие лишних элементов, реальные клавиши закрытия,
Ctrl+A/P/N, выделение, live updates, Escape, повторное открытие, viewport 360×420,
переход между окнами и toolbar popup. Нативный Ctrl+W проверяется отдельно от
синтетического CDP-ввода, который может обходить браузерные accelerators.

## Быстрый повторный вызов · 0.3.0

Первый вызов создаёт один iframe в документе страницы. При закрытии контейнер
выходит из popover top layer, а iframe остаётся загруженным. Повторный вызов
проверяет существующий host и показывает его без `executeScript`, записи в
storage, повторной загрузки HTML, JavaScript или CSS. При навигации, перезагрузке
или выгрузке вкладки браузером документ и этот кеш создаются заново.

Скрытый UI кеширует обновления вкладок без перестройки DOM и без обновления
подписей времени. При открытии сбрасываются запрос и выделение, показывается
кешированный список, затем фокусируется input. Скрытый iframe не перехватывает
фокус и не закрывает страницу подложкой.

Escape сразу скрывает документ UI и отправляет `tabs.sendMessage` непосредственно
в content script своей вкладки, не дожидаясь service worker. Content script
синхронно закрывает popover и восстанавливает фокус. Показывать, скрывать и
фокусировать UI могут только runtime-сообщения того же расширения с правильными
токеном и идентификатором вкладки. Номер поколения сообщения защищает от поздних
ответов после быстрого закрытия/открытия. `window.postMessage` не используется.

Перед переключением вкладки пикер скрывается; worker дожидается кадра страницы
без панели. Это сохраняет исправление вспышки старого меню при A → B → A,
не уничтожая iframe. Если скрытый UI потерял связь с worker, повторное открытие
показывает кеш и переподключает канал для получения свежих данных.

Компромисс: каждая страница, на которой уже вызывался пикер, сохраняет один
загруженный iframe. В остальные страницы расширение заранее не внедряется.
Первое открытие включает загрузку UI; повторные быстрее. Измерения первого и
повторных открытий и Escape записываются интеграционным тестом в
`test-results/results.json`: время измеряется от отправки сочетания до ближайшего
кадра с нужным состоянием popover, вместе с затратами на доставку тестового ввода.

После обновления расширения перезагрузите страницы для замены content script.

## Исправление подложки · 0.3.1

Скрытый host явно получает `display: none !important`, `visibility: hidden`
и `pointer-events: none`. Одного `hidePopover()` было недостаточно: сброс
`all: initial !important` перекрывал стандартный CSS закрытого popover.
При открытии эти свойства явно восстанавливаются. Iframe остаётся в кеше.

Интеграционный тест проверяет не только `:popover-open`, но и реальное
попадание клика в кнопку страницы после Escape, повторной горячей клавиши
и возврата A → B → A в одном и разных окнах. Перед исправлением эта проверка
воспроизводила блокировку кликов, после исправления проходит.
